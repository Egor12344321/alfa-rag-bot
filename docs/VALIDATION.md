## Отдельная проверка на PostgreSQL / pgvector

Среда блокирует создание обычных сетевых/Unix-сокетов. Поэтому тестовый PostgreSQL
16.2 с pgvector 0.6.2 использован через его стандартный stand-alone backend и каналы
stdin/stdout. Это реальный SQL-движок; PostgreSQL в предлагаемом Compose — версии 17.

На нём выполнены:

- DDL миграций `20261115_01`, `20261115_03` и `20261115_04`;
- полный импорт **1 425 материалов и 4 219 чанков** через код `knowledge.repository`;
- повторный импорт: сохранён тот же run, дубли материалов и чанков не созданы;
- косинусный поиск: запрос исходным вектором возвращает соответствующий текст
  с практически нулевой дистанцией;
- рекомендации по вектору курса, получение его карточки и фильтр только бесплатных материалов;
- отказ при несовпадении модели и при несовпадении размерности вектора;
- искусственная ошибка записи чанка: транзакция откатилась, частичный материал
  отсутствует, неудачный run помечен failed, предыдущий active run сохранён.

## Что не проверено в этой среде

10 пропущенных pytest-тестов требуют `TEST_DATABASE_URL` и обычное клиентское
подключение: два теста PostgreSQL-хранилища диалогов, семь тестов транзакций
напоминаний/worker и один тест полного импорта через SQLAlchemy/psycopg.
Они включены в архив для прогона в обычной среде команды.

Живой polling Telegram, запросы к DeepSeek с вашим ключом, фактическое скачивание
и инференс BGE-M3, а также Docker-сборка не запускались. Установлены и проверены
базовые зависимости; модельный стек выделен отдельно и разрешает зависимости,
но не загружался для имитации успешного реального ответа.

Миграция `20261115_02` переноса раннего public-MVP не прогонялась на вашей текущей БД,
поскольку её содержимое не предоставлено. Проект не обращался к рабочим сервисам
команды и не изменял существующие базы или тома.

## Что прогнать у команды

1. Следовать `README.md`, заполнить ключи и выполнить `docker compose up -d --build bot`.
2. Убедиться, что migrate/load_index завершились с кодом 0, bot начал polling.
3. При необходимости прогреть модель командой `python -m alfa_bot.check --warm-model`.
4. Выполнить сценарии README: вопрос → уточнение → ответ, отдельная карточка,
   черновик → подтверждение → доставка, изменение частоты/отключение/удаление.
5. Для полного pytest-прогона задать отдельный `TEST_DATABASE_URL` с pgvector.
