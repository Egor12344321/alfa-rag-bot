# Проверка трека 2

## Локальные прогоны

- Дамп восстановлен в PostgreSQL 17. Базовая миграция сохранила историю, профиль и напоминание.
- Подготовлено 5 728 фрагментов и 1 426 карточек. Источники: 802 статьи, 247 документов, 351 термин и 26 курсов, среди них 1 платный.
- Запись всего корпуса, cosine-поиск и повторный импорт проверены с контрольными векторами в pgvector. С BGE-M3 проверены демобаза и выборка настоящих материалов.
- На демобазе с BGE-M3 и Qwen получены короткий ответ с источником, уместная платная карточка, честный отказ и черновик напоминания.
- На выборке из дампа с BGE-M3 и Qwen получены определение франшизы, ответ о названии бренда и карточка платного курса по УСН на маркетплейсах. На CPU с малым запасом памяти тесты прошли в режиме одной резидентной модели. Первые запросы к Qwen в этом режиме занимали около 100 секунд каждый.
- В каталоге мало явных указаний об уровне. Тип доступа и тема берутся из каталога, уровень применяется при наличии признака в названии или описании.
- На PostgreSQL с подменённым Telegram API проверены доставка разового и повторяющегося напоминаний, смена частоты, отключение и отсутствие повторной доставки.
- Конфигурация Compose проходит проверку. Docker Engine и токен нужны для проверки контейнеров и живой доставки.

## Как повторить

    uv sync --locked --extra dev
    uv run pytest -q
    uv run ruff check .
    uv run alembic upgrade head --sql

Для PostgreSQL-тестов задайте ALFA_TEST_POSTGRES_URL на отдельный PostgreSQL с pgvector и правом создавать временную БД. Проверка миграций и сборка образа настроены в GitHub Actions. Сценарии Telegram приведены в [README](../README.md).

## Оценка качества

Составьте набор из вопросов с ожидаемыми ссылками и вопросов без ответа. Измерьте попадание нужного материала в top-5, частоту ложных совпадений и p95 задержки. Отдельно проверьте, подтверждают ли источники факты из ответа и меняется ли подбор материалов для разных профилей.

## Бизнес-эффект

Случайно распределить аккаунты Альфа-Курса 50/50. Группа A получает обычный опыт платформы, группа B также получает приглашение в бот. Сравнивать показатели по всем назначенным пользователям.

- Покупки — доля пользователей, купивших хотя бы один образовательный продукт за 30 дней.
- Возврат — среднее число разных дней с визитом за первые 7 дней на назначенного пользователя.
- Обратная связь — доля отключений среди включивших напоминания и доля жалоб на рекомендации.
- Воронка — переход из консультации к материалу, доставка запрошенного напоминания и возврат к обучению.

Покупки и визиты фиксирует аналитика платформы. Гипотеза пилота: переход к подходящему материалу и добровольные напоминания помогают продолжить обучение и повышают конверсию.
