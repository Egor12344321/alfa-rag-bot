## Что обнаружено

| Область | Состояние в полученных архивах | Решение |
| --- | --- | --- |
| Telegram | Ветка assistant содержит Router-заглушку | Подключены ваши обработчики команд, сообщений и callbacks |
| Хранилище assistant | Protocol и `UnconfiguredAssistantRepository`, нет реализации сохранения | Подключены реальные репозиторий PostgreSQL и адаптер состояния |
| LLM | Точка сборки создаёт `UnconfiguredLLM`, несмотря на имеющийся отдельный клиент | В рабочей сборке используется настроенный JSON-клиент DeepSeek |
| Результат assistant | `HandledTurn` с UUID, без DTO ответа для ваших обработчиков | Адаптер формирует `Reply`, `Answer`, источники, рекомендации и черновик |
| Напоминания | Разные API: UUID владельца и `prepare` против Telegram ID и операций вашего сервиса | Добавлен адаптер; исполнение и управление остаются в отдельном `reminders` |
| Подтверждение | Assistant возвращает только текст предварительного просмотра | Возвращается серверный черновик с ID, сроком действия и кнопками |
| Материалы | Рекомендация склеивается с текстом ответа | Текст ответа и карточки материалов отправляются отдельными сообщениями |
| Knowledge | Собственная SQL-схема и psycopg-подключение, несовместимые со старым индексом | Подключены реальная реализация knowledge и миграция схемы |
| Эмбеддинги | Вклад knowledge рассчитан на E5/384, готовый комплект — BGE-M3/1024 | Размерность хранится в run; проверяются модель, ревизия и размерность |
| История | Нет работающей сборки для сохранения диалога | Сохраняются история, профиль, исходный вопрос и незавершённые параметры напоминания |
| Повтор сообщения | Сравнение только с последним сообщением недостаточно | Результаты сохраняются с ключом `(user_id, update_id)` в `app.turn_results` |
| «Этот курс» | Поиск идёт только по знаниям, где нет содержимого курсов | Используются реально показанные материалы, затем поиск и каталог |
| Настройки и запуск | Ветки имеют разные точки сборки, зависимости и переменные | Одна точка `python -m alfa_bot.main`, общий Compose и инструкции |

## Рабочий поток

Telegram создаёт `UserRequest`. `IntegratedAssistant` загружает диалог и подключает
`AssistantService` из ветки разработчика. Сервис определяет намерение, использует
`KnowledgeService` из второй ветки и проверяет ответ. Адаптер сохраняет результат
и формирует DTO вашего интерфейса. Telegram отправляет ответ и отдельные карточки.

При просьбе о напоминании assistant собирает параметры. Ваш сервис сохраняет
серверный черновик. Только callback подтверждения создаёт действующее напоминание.
Worker доставляет его через ваш Telegram-транспорт. Ссылки и тексты платных курсов
не используются как фрагменты для ответа: каталог содержит их публичные описания.

## Миграции

- `20261115_01`: рабочие профили, диалоги, история, напоминания и старый индекс.
- `20261115_02`: перенос совместимых данных раннего MVP из public.
- `20261115_03`: прежняя схема индекса сохраняется как `kb_v04`, устанавливается схема knowledge.
- `20261115_04`: сохранённые результаты сообщений для дедупликации.

В старом готовом формате не сохранялось точное число токенов каждого чанка.
При переносе в новую схему `token_count=0` означает «неизвестно»; тексты и векторы
переносятся без пересчёта. Новые исходные материалы проходят чанкинг с подсчётом токенов.

## Что требуется при запуске у команды

Нужны реальные ключи Telegram и DeepSeek, PostgreSQL/pgvector и локальная модель
из manifest. Модель впервые загружается в кеш, готовые векторы уже есть в архиве.
В этой среде живые Telegram/DeepSeek-запросы и Docker-сборка не выполнялись.
Обычные клиентские подключения к PostgreSQL ограничены средой; для проверки
SQL использован PostgreSQL с pgvector через стандартный stand-alone backend.
Результаты и оставшиеся проверки перечислены в `VALIDATION.md`.

Предлагаемый коммит: `feat: integrate assistant, knowledge and telegram reminders`.
