# Альфа-Курс: ИИ-помощник для предпринимателей в Telegram

Прототип для **Hack&Change 2026**, кейс «Альфа-Курс: знания в нужный момент», **трек 2**.

Помощник отвечает на бизнес-вопросы по предоставленной базе знаний, уточняет ситуацию пользователя,
подбирает материалы «Альфа-Курса» и создаёт напоминания об обучении и делах.

Проект решает задачу перехода от общего вопроса к конкретному действию: получить ответ,
открыть подходящий материал или запланировать его изучение. Ожидаемый бизнес-эффект — увеличение
возвращаемости на платформу и конверсии в образовательные продукты. Рост этих показателей
является гипотезой для последующей проверки, а не измеренным результатом прототипа.

Бот: @AlfaNavigatorBot

## Возможности

- Ответы по базе знаний с кликабельными ссылками на использованные источники.
- Уточнение неоднозначного вопроса и продолжение диалога с учётом ответа пользователя.
- Сохранение истории, стадии бизнеса, отрасли, цели, опыта, налогового режима и часового пояса.
- Рекомендации материалов с известными условиями доступа; карточки отправляются отдельно от ответа.
- Разовые, ежедневные, еженедельные и ежемесячные напоминания.
- Подтверждение создания напоминания, изменение частоты, отключение, включение и удаление.
- Сохранение состояния в PostgreSQL между перезапусками приложения.
- Отказ от уверенного ответа, если подходящих сведений в базе не найдено.

Бот работает **в личных чатах Telegram**.

## Быстрая проверка для жюри

1. Распаковать проект целиком, включая `private_data/prepared`.
2. Создать `.env` из `.env.example`, заполнить `BOT_TOKEN` и `DEEPSEEK_API_KEY`, задать пароль БД.
3. Выполнить единую команду запуска:

   ```powershell
   docker compose up -d --build bot
   ```

4. Дождаться успешного завершения `migrate` и `load_index`. При первом запуске подготовить модель
   по разделу [«Первая загрузка модели»](#первая-загрузка-модели).
5. Открыть в Telegram бота, которому принадлежит заданный `BOT_TOKEN`, и отправить `/start`.
6. Пройти [сценарии проверки](#команды-и-сценарии-проверки): консультация, уточнение,
   рекомендация, подтверждение напоминания и его фактическая доставка.

Публичный HTTP-интерфейс не требуется: Telegram подключается через long polling.

## Требования и зависимости

Для запуска через Docker:

- Docker Engine с Docker Compose v2 либо Docker Desktop с запущенным Docker Engine.
- Интернет для загрузки образов и зависимостей; при первой подготовке — для загрузки BGE-M3.
- Доступ к Telegram Bot API и DeepSeek API во время работы бота.
- Токен Telegram-бота и действующий API-ключ DeepSeek.
- Ресурсы Docker для работы PostgreSQL и локальной модели BGE-M3. GPU не обязателен:
  стандартная конфигурация использует CPU. Строгий минимальный объём RAM в прототипе не измерен.

| Компонент | Использование |
| --- | --- |
| Python 3.12 | Версия Python в Docker-образе |
| aiogram 3 | Telegram-сообщения, команды и кнопки |
| PostgreSQL 17 + pgvector | Состояние приложения и векторный поиск |
| SQLAlchemy 2, psycopg 3 | Асинхронная работа с БД |
| Alembic | Миграции схемы |
| Pydantic, pydantic-settings | DTO, проверка структурированных ответов и настройки |
| DeepSeek API, `deepseek-flash` | Определение намерения и генерация ответа в JSON |
| Sentence Transformers, PyTorch CPU | Локальное вычисление эмбеддинга вопроса |
| `BAAI/bge-m3` | Embedding-модель, размерность 1024 |
| NumPy | Чтение готовых эмбеддингов материалов |

Точные версии базовых зависимостей зафиксированы в [requirements.lock](requirements.lock),
локального модельного стека — в [requirements-embeddings.lock](requirements-embeddings.lock).
Dockerfile отдельно устанавливает CPU-версию `torch==2.15.0`.

## Получение токенов и ключей

### Telegram

1. Открыть [@BotFather](https://t.me/BotFather) в Telegram.
2. Создать бота командой `/newbot` либо выбрать существующего через `/mybots` и получить его токен.
3. Записать значение в `.env`:

   ```dotenv
   BOT_TOKEN=your_telegram_bot_token
   ```

4. После запуска открыть именно этого бота и отправить `/start`.

Для одного токена должен работать один polling-процесс. При переходе на эту сборку остановите
предыдущий процесс, использующий тот же токен.

### DeepSeek

1. Создать API-ключ в [кабинете DeepSeek](https://platform.deepseek.com/).
2. Убедиться, что аккаунт позволяет выполнять API-запросы к выбранной модели.
3. Заполнить `.env`:

   ```dotenv
   DEEPSEEK_API_KEY=your_deepseek_api_key
   DEEPSEEK_BASE_URL=https://api.deepseek.com
   DEEPSEEK_MODEL=deepseek-flash
   ```

Используется endpoint `POST /chat/completions`, JSON-ответы и отключённый режим thinking.
Запросы к DeepSeek могут тарифицироваться провайдером. Описание API и актуальные условия:
[документация DeepSeek](https://api-docs.deepseek.com/).

Ключи передаются через переменные окружения. Рабочий `.env` не входит в сдаваемый пакет.

## Запуск через Docker

Команды выполняются из корня проекта — каталога с `compose.yaml`.

### 1. Настроить окружение

PowerShell:

```powershell
Copy-Item .env.example .env
notepad .env
```

Linux/macOS:

```bash
cp .env.example .env
```

Обязательно заполните `BOT_TOKEN`, `DEEPSEEK_API_KEY` и выберите `POSTGRES_PASSWORD`.
В шаблоне указан демонстрационный пароль `change_me` — замените его для своей установки.
Основная модель DeepSeek в шаблоне — `deepseek-flash`.

Параметры BGE-M3 оставьте соответствующими готовому комплекту:

```dotenv
EMBEDDING_MODEL=BAAI/bge-m3
EMBEDDING_REVISION=5617a9f61b028005a4858fdac845db406aefb181
EMBEDDING_DIMENSION=1024
```

### 2. Запустить приложение

```powershell
docker compose up -d --build bot
```

Compose выполняет последовательность:

| Сервис | Назначение | Ожидаемое состояние |
| --- | --- | --- |
| `db` | PostgreSQL с pgvector | `Up`, `healthy` |
| `migrate` | Применение миграций | `Exited (0)` |
| `load_index` | Проверка и импорт готового комплекта | `Exited (0)` |
| `bot` | Telegram polling и планировщик напоминаний | `Up` |

Проверить состояние и последние сообщения:

```powershell
docker compose ps -a
docker compose logs --tail=100 migrate load_index bot
```

`Exited (0)` у `migrate` и `load_index` означает успешное завершение служебной операции.
Загружать исходный дамп или пересчитывать эмбеддинги материалов для этого запуска не нужно.

### 3. Проверить конфигурацию

После запуска зависимостей:

```powershell
docker compose run --rm --no-deps bot python -m alfa_bot.check
```

Команда проверяет наличие обязательных настроек, версию схемы и соответствие модели активному индексу.
Она не выполняет тестовый запрос к Telegram или DeepSeek.

## Первая загрузка модели

Готовые векторы материалов и сама модель — разные компоненты. Для нового вопроса необходимо
локально вычислить его вектор той же BGE-M3, которой были подготовлены материалы.

При первом поиске библиотека загружает веса [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3).
Файл весов занимает около 2,27 ГБ; также загружаются конфигурация и токенизатор.
Продолжительность зависит от соединения, диска и ресурсов Docker.

В текущей реализации модель инициализируется лениво. Поэтому сообщение
`Application ready; polling and reminders starting` ещё не подтверждает готовность модели,
а первый бизнес-вопрос может обрабатываться заметно дольше последующих.

**Перед демонстрацией отдельно завершите подготовку модели:**

```powershell
docker compose stop bot
docker compose run --rm --no-deps bot python -m alfa_bot.check --warm-model
```

Команда использует уже работающую БД, применённые миграции и загруженный индекс.
Дождитесь её успешного завершения и строки:

```text
Local model: BAAI/bge-m3, dimension=1024: OK
```

Затем запустите существующий контейнер бота:

```powershell
docker compose start bot
```

Файлы сохраняются в томе `model_cache`. Следующий процесс использует этот кеш,
но загрузка модели с диска в оперативную память всё равно занимает время.
Дополнительно выполните один пробный бизнес-запрос перед показом жюри.

Не меняйте BGE-M3 на E5, сохраняя прежний индекс: модель, ревизия и размерность обязаны совпадать.

## Переменные окружения

Полный шаблон находится в [.env.example](.env.example). Значения ниже соответствуют стандартной сборке.

### Telegram и генерация ответов

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | Пусто | Обязательный токен Telegram-бота |
| `DEEPSEEK_API_KEY` | Пусто | Обязательный ключ DeepSeek API |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | Адрес API |
| `DEEPSEEK_MODEL` | `deepseek-flash` | Имя модели генерации |
| `LLM_TIMEOUT` | `60` | Таймаут HTTP-клиента, секунды |
| `LLM_MAX_TOKENS` | `4000` | Ограничение длины ответа модели |
| `LLM_RETRIES` | `2` | Число повторов при предусмотренных клиентом временных ошибках |

Один пользовательский запрос может включать несколько вызовов LLM; значение `LLM_TIMEOUT`
не является общим ограничением длительности всей обработки сообщения.

### База данных

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `POSTGRES_DB` | `alfa_bot` | Рабочая БД |
| `POSTGRES_USER` | `alfa_bot` | Пользователь БД |
| `POSTGRES_PASSWORD` | `change_me` в шаблоне | Пароль, задаваемый для своей установки |
| `POSTGRES_PORT` | `5433` | Порт PostgreSQL на компьютере |
| `DATABASE_URL` | Строка из шаблона | Подключение при запуске Python на компьютере |
| `SOURCE_DATABASE_URL` | Пусто | Необязательный источник для отдельного импорта новых материалов |

В Compose адрес `db:5432` формируется из отдельных параметров. `DATABASE_URL` из файла
используется при запуске Python вне контейнера. При изменении учётных данных или порта
обновите эту строку для локального запуска.

Пароль `POSTGRES_PASSWORD` применяется при первоначальном создании БД. Изменение значения
в `.env` не меняет пароль существующей роли в уже инициализированном томе PostgreSQL.

### Модель, поиск и диалог

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `EMBEDDING_MODEL` | `BAAI/bge-m3` | Локальная embedding-модель |
| `EMBEDDING_REVISION` | `5617a9f61b028005a4858fdac845db406aefb181` | Точная ревизия готового индекса |
| `EMBEDDING_DIMENSION` | `1024` | Размерность вектора |
| `EMBEDDING_DEVICE` | `cpu` | Устройство вычисления; Docker-сборка рассчитана на CPU |
| `EMBEDDING_THREADS` | `4` | Число потоков PyTorch на CPU |
| `EMBEDDING_BATCH_SIZE` | `8` | Размер пакета вычисления эмбеддингов |
| `HF_HUB_OFFLINE` | `0` | `1` — работа Hugging Face Hub с локальным кешем; включать после подготовки файлов |
| `TOP_K` | `5` | Число извлекаемых фрагментов при консультации |
| `SCORE_THRESHOLD` | `0.6` | Порог сходства для фрагментов ответа: `similarity = 1 - cosine_distance` |
| `RECOMMENDATION_LIMIT` | `1` | Лимит автоматически предлагаемых карточек; `0` отключает автоматические рекомендации |
| `HISTORY_LIMIT` | `10` | Максимальное число сохраняемых сообщений истории диалога |

Явный запрос пользователя подобрать материал обрабатывается и при отключённых автоматических рекомендациях.
Порог — мера сходства векторов, а не вероятность правильности ответа.

`EMBEDDING_CACHE_DIR` можно задать при запуске Python на компьютере. В предоставленном Compose
каталог модели закреплён как `/app/private_data/models` и подключён к тому `model_cache`.

## Запуск Python на компьютере

Этот режим полезен для разработки. Нужен Python 3.12 и PostgreSQL с установленным pgvector.
Базу можно запустить из Compose:

```powershell
docker compose up -d db
```

Создайте `.env`, заполните токены и настройте `DATABASE_URL` на адрес БД с компьютера.
Например, для порта 5433:

```dotenv
DATABASE_URL=postgresql+psycopg://alfa_bot:your_database_password@localhost:5433/alfa_bot
```

В пароле внутри URL специальные символы должны быть корректно закодированы.
В контейнерной конфигурации Compose пароль передаётся отдельным полем.

PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.lock -r requirements-embeddings.lock
python -m pip install --no-deps -e .
python -m alembic upgrade head
python -m alfa_bot.knowledge.bundle
python -m alfa_bot.check --warm-model
python -m alfa_bot.main
```

На Linux/macOS активация окружения: `source .venv/bin/activate`.
Перед локальным запуском остановите контейнер `bot`, если он использует тот же Telegram-токен.
Строки подключения с префиксом `postgresql+asyncpg://` принимаются и приводятся приложением к psycopg.


## План проверки бизнес-эффекта

После интеграции с платформой предлагается проверить гипотезу A/B-тестом.
Это план следующего этапа; в текущем прототипе такой эксперимент и измерение покупок не проводились.

| Элемент | Предложение |
| --- | --- |
| Гипотеза | Контекстная консультация, рекомендации и согласованные напоминания увеличивают возвращаемость и покупки |
| Контроль | Текущий путь поиска материалов на платформе |
| Эксперимент | Доступ к Telegram-помощнику |
| Основная метрика | Доля назначенных в группу пользователей, совершивших покупку за согласованный период |
| Дополнительная метрика | Число дней посещения платформы на пользователя за тот же период |
| Диагностические метрики | Открытия материалов, подтверждение напоминаний, повторные обращения |
| Ограничивающие метрики | Отключение уведомлений, жалобы, ошибки и длительность ответа |

Пользователей нужно распределять между группами случайно. Период наблюдения и достаточный размер
выборки определяются до запуска. Потребуются события платформы о переходах, посещениях и покупках;
бот сам по себе не подтверждает эти действия. Рост числа сообщений в Telegram не заменяет
измерение посещений «Альфа-Курса».
