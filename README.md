# Альфа-Курс: объединённый проект 0.5.0

В проекте соединены логика из `assistant.zip`, поиск и импорт из `knowledge.zip`,
последние сохранённые Telegram-обработчики, карточки и напоминания.
Подробный разбор изменений — в `docs/MERGE_REPORT.md`.

## Быстрый запуск через Docker Desktop

Распакуйте архив в **отдельную папку**, откройте её в PowerShell.

```powershell
Copy-Item .env.example .env
```

Заполните в `.env`:

- `BOT_TOKEN` — токен вашего Telegram-бота;
- `DEEPSEEK_API_KEY` — ключ DeepSeek;
- `DEEPSEEK_MODEL` — доступная вашему ключу модель, поддерживающая JSON-ответы.

Остальные параметры уже согласованы с готовым индексом. Затем:

```powershell
docker compose up -d --build bot
docker compose ps -a
docker compose logs -f bot
```

Compose последовательно поднимает PostgreSQL с pgvector, применяет миграции,
импортирует готовый индекс и запускает Telegram вместе с планировщиком.
`migrate` и `load_index` должны завершиться с кодом `0`; `bot` и `db` продолжают работать.

Первый бизнес-вопрос загружает BGE-M3 в кеш модели. Для этого нужен доступ
к Hugging Face и свободное место для модели; последующие запуски используют тот же том.
При желании загрузите модель заранее:

```powershell
docker compose run --rm bot python -m alfa_bot.check --warm-model
```

Если порт `5433` уже занят другой БД, поменяйте `POSTGRES_PORT` в `.env`, например
на `5434`. Для Python на хосте укажите этот же порт в `DATABASE_URL`.
Внутри Compose адрес БД остаётся `db:5432`.
Не запускайте старый и новый polling-процесс с одним токеном одновременно.

## Готовые данные уже включены

В `private_data/prepared/` находятся **все три файла**:

| Файл | Назначение |
| --- | --- |
| `chunks.jsonl` | 4 219 чанков с метаданными 1 425 материалов |
| `embeddings.npy` | Готовые нормализованные векторы BGE-M3 размерности 1024 |
| `manifest.json` | Контрольные суммы, точная модель и её ревизия |

В составе: 802 статьи, 247 документов, 350 терминов и 26 карточек курсов.
Импорт не пересчитывает эмбеддинги и не требует исходного дампа.
При повторном импорте неизменного комплекта используется существующий индекс.
Не подставляйте E5 к этим BGE-векторам: модель, ревизия и размерность должны совпадать.

Эти данные относятся к заданию хакатона. `private_data` исключена из Git.

## Запуск Python на Windows

Нужны Python 3.12 и доступный PostgreSQL с pgvector. Например, поднимите только БД:

```powershell
docker compose up -d db
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.lock -r requirements-embeddings.lock
python -m pip install --no-deps -e .
python -m alembic upgrade head
python -m alfa_bot.knowledge.bundle
python -m alfa_bot.check
python -m alfa_bot.main
```

`DATABASE_URL` в `.env` должен указывать на рабочую БД на хосте.
Старые строки вида `postgresql+asyncpg://...` принимаются: приложение приводит
подключение к psycopg, необходимому реализации `knowledge`.

## Проверка бота

1. `/start`, затем «Как привлечь клиентов?» → уточнение при необходимости.
2. «У меня кофейня» → продолжение исходного вопроса с сохранённым контекстом.
3. «Подбери бесплатный курс по маркетингу» → отдельная карточка найденного курса
   либо явное сообщение, что подходящего материала в каталоге нет.
4. «Напомни пройти этот курс завтра в 10:00» → черновик с кнопкой подтверждения.
5. Подтвердите, откройте `/reminders`: измените частоту, отключите, включите и удалите запись.
6. `/profile` показывает сохранённые сведения; `/cancel` отменяет текущий запрос;
   `/new` очищает диалог и профиль, сохраняя подтверждённые напоминания.

Часовой пояс по умолчанию — `Europe/Moscow`; другой пояс можно явно указать в сообщении.
Повторы: один раз, ежедневно, еженедельно, ежемесячно. Интервалы вроде «раз в две недели»
бот просит заменить поддерживаемым вариантом и не сохраняет их как обычный еженедельный повтор.

## Файлы и границы модулей

| Путь | Ответственность |
| --- | --- |
| `src/alfa_bot/assistant/service.py` | Логика разработчика assistant: намерение, уточнение, поиск, проверка ответа |
| `src/alfa_bot/assistant/integration.py` | Связь этой логики с PostgreSQL, вашим Telegram-контрактом и напоминаниями |
| `src/alfa_bot/assistant/repository.py` | Профиль, история, состояние диалога, версии и кеш обработанных сообщений |
| `src/alfa_bot/knowledge/` | Реализация разработчика knowledge: источники, чанкинг, поиск, рекомендации, публикация индекса |
| `src/alfa_bot/reminders/` | Ваш отдельный модуль: расписания, черновики, подтверждение, управление, доставка |
| `src/alfa_bot/bot/` | Ваш Telegram-интерфейс: сообщения, карточки, кнопки, HTML, транспорт |
| `src/alfa_bot/contracts.py` | Публичные DTO интерфейса Telegram и напоминаний |
| `src/alfa_bot/domain.py` | Внутренние DTO, согласованные между contributed assistant и knowledge |
| `src/alfa_bot/main.py` | Единственная точка сборки и запуска |

Изменять Telegram ради внутренних форматов `knowledge` не нужно: преобразования
находятся в `assistant/integration.py`.

## Миграции и существующие базы

В Compose используется отдельное имя проекта `alfa-course-integrated` и свой том БД.
Старые тома и данные не удаляются.

Для предыдущей версии с миграциями `20261115_01`/`20261115_02` достаточно
`python -m alembic upgrade head`: таблицы профиля и напоминаний сохраняются,
прежний индекс переносится в схему `kb_v04`, новая схема `kb` получает индекс
из включённого комплекта.

Для раннего MVP миграция `20261115_02` умеет скопировать совместимые записи
из `public.reminders`. Исходная таблица сохраняется.

Базы из веток разработчиков с историей `0001_initial`/`0002_catalog_policy`
имеют другую структуру: для этого архива используйте отдельную рабочую БД,
как в предлагаемом Compose. Автоматического переноса их диалогов нет.

## Импорт новых исходных материалов

Это отдельная операция; для обычного запуска с готовым комплектом она не нужна.
Настройте `SOURCE_DATABASE_URL` и проверьте mapping из `knowledge/expanded_sources.py`:
он допускает только явно перечисленные и разрешённые источники.

```powershell
python -m alfa_bot.knowledge.cli
```

Исходная БД открывается только для чтения. Добавление других ID требует обновить
проверенный mapping. Бот при ответах обращается к своей рабочей БД, а не к исходному дампу.

## Тесты

```powershell
python -m pip install -e ".[dev]"
python -m pytest -q
python -m ruff check src tests migrations
```

Тесты Telegram используют записывающий транспорт, вызовы DeepSeek — тестовые ответы.
Для проверок реальных транзакций задайте `TEST_DATABASE_URL` на отдельную БД
с именем, заканчивающимся на `_test` или начинающимся с `test_`. Эти тесты очищают
таблицы **только тестовой БД**, поэтому рабочий `DATABASE_URL` вместо него не подходит.
Подробности фактической проверки этой сборки — в `docs/VALIDATION.md`.
