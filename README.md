# Альфа-Курс: knowledge + assistant

Реализация для текущего Telegram-бота с контрактом `AssistantPort.handle()`.
Python 3.12+, PostgreSQL, aiogram, DeepSeek. В архиве есть исходники обоих
модулей, подключение через `main.py`, текущий модуль reminders и тесты.

## Что реализовано

- `knowledge`: загрузка подготовленных статей, поиск релевантных фрагментов,
  импорт каталога, подбор карточек и фильтрация платных/бесплатных материалов.
- `assistant`: классификация запроса, одно уточнение для общего бизнес-вопроса,
  ответ по найденным фрагментам, рекомендации, сбор данных напоминания.
- Память: история последних 12 сообщений, профиль и незаконченный запрос
  хранятся в PostgreSQL отдельно для каждого Telegram-пользователя.
- Карточки берутся из каталога; LLM возвращает идентификаторы фрагментов.
  Сервер проверяет эти идентификаторы и добавляет номера источников.
- Напоминание возвращается как `ReminderIntent`. Создание в БД выполняют
  существующие хендлеры и `ReminderService` после нажатия «Подтвердить».

## Быстрый запуск в существующем проекте

1. Скопируйте содержимое папки `alfa-rag-bot` в корень своего проекта.
   Проверьте изменения перед заменой собственных файлов. Текущие контракты
   ассистента сохранены без изменений. Подробности — `docs/INTEGRATION.md`.
2. Из корня проекта установите зависимости:

```powershell
python -m pip install -e ".[dev]"
```

3. Дополните существующий `.env` значениями из `.env.example`:

```dotenv
BOT_TOKEN=ваш_токен_telegram
DATABASE_URL=postgresql+asyncpg://alfa_bot:change_me@localhost:5433/alfa_bot
DEEPSEEK_API_KEY=ваш_ключ_deepseek
DEEPSEEK_MODEL=deepseek-flash
```

Путь `.env` определяется от корня проекта, поэтому запуск не зависит от
выбранной папки терминала после установки пакета. Для команд ниже работайте из корня.
Пустые `BOT_TOKEN` и `DATABASE_URL` допустимы только для сборки индекса/поиска.
Полный запуск проверяет обязательные параметры.

4. Положите **ранее сформированный public-only** `article_chunks.jsonl` в
   `private_data/article_chunks.jsonl`. Исходные выгрузки в архив не включены.

5. Соберите индекс. Первый вариант работает без скачивания embedding-модели:

```powershell
python -m alfa_bot.knowledge.ingest --chunks private_data/article_chunks.jsonl --backend bm25
```

Для текущей базы результат: 801 материал, 7 085 фрагментов для ответов,
801 документ каталога для рекомендаций статей.

6. Проверьте поиск без Telegram и DeepSeek:

```powershell
python -m alfa_bot.knowledge.search "Как привлечь клиентов в кофейню?"
```

7. Запустите бота:

```powershell
python -m alfa_bot.main
```

При запуске создаются отсутствующие таблицы `reminders` и `assistant_dialogs`.
`checkfirst=True` не изменяет схему уже существующих таблиц; если у вас они
устарели, потребуется отдельная миграция. Создание не удаляет существующие данные.

## Семантический поиск E5

BM25 использует совпадения слов с русским стеммингом. Чтобы находить близкие
по смыслу формулировки, установите дополнительную зависимость и пересоберите индекс:

```powershell
python -m pip install -e ".[semantic]"
python -m alfa_bot.knowledge.ingest --chunks private_data/article_chunks.jsonl --backend hybrid
```

Используется `intfloat/multilingual-e5-small`. Документы кодируются с префиксом
`passage:`, вопросы — с `query:`. Модель скачивается при первом использовании;
после скачивания её можно использовать из локального кеша.

В гибридном режиме результаты BM25 и cosine similarity объединяются через
Reciprocal Rank Fusion. Индекс хранит название модели, запросы используют ту же модель.
E5 получает до 512 токенов на документ; длинные исходные фрагменты для BM25
сохраняются целиком. Порог cosine 0.82 — начальное значение для настройки на вашем eval.

Для этого объёма знаний индекс хранится локально: JSON + `vectors.npy`, когда
включена семантика. PostgreSQL используется для диалогов и напоминаний.
Это самостоятельная реализация поиска для текущего JSONL, а не реализация
старого незавершённого каркаса `kb.materials/kb.chunks` с pgvector.
Векторные и текстовые данные не загружаются в исходную БД организаторов.

## Как добавить курсы

В доступных файлах есть статьи, но нет достоверного каталога курсов.
Поэтому готовый бот не выдаёт выдуманные курсы и цены: на просьбу подобрать
курс при отсутствии подходящих записей сообщает, что их нет в загруженном каталоге.
Рекомендации статей работают по имеющимся данным.

Подготовьте `private_data/catalog.jsonl`: одна карточка на строку.
Ниже только описание формата — замените поля реальными значениями из каталога:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | строка | Уникальный исходный ID, не совпадающий с ID статьи |
| `title` | строка | Название |
| `url` | строка | Настоящий HTTP(S) URL |
| `kind` | строка | `course`, `article`, `other` |
| `description` | строка | Описание тем и пользы |
| `access` | строка | `free`, `paid`, `unknown` |
| `price` | строка/null | Цена с валютой из каталога, если известна |
| `is_public` | bool | `true` для публичной карточки |
| `is_active` | bool | `true` для действующего материала |
| `is_closed` | bool | Необязательно; `true` исключает карточку |

```powershell
python -m alfa_bot.knowledge.ingest --chunks private_data/article_chunks.jsonl --catalog private_data/catalog.jsonl --backend bm25
```

Для гибридного индекса укажите `--backend hybrid`.
Опубликованная карточка платного курса может использоваться для рекомендации.
Её содержимое не становится источником ответа: JSONL каталога индексируется
только с назначением `catalog`. Неизвестная стоимость не считается бесплатным доступом.
Без явных `is_public: true` и `is_active: true` карточка не импортируется.

## Как работает память

Пример:

1. Пользователь: «Как привлечь клиентов?».
2. Бот: «Какой у вас бизнес и вы уже открылись или только планируете?».
3. В `assistant_dialogs.pending` сохраняется исходный вопрос.
4. Пользователь: «Кофейня, открылись месяц назад».
5. Ассистент получает предыдущие сообщения и pending, дополняет профиль,
   ищет материалы с учётом кофейни и отвечает на исходный вопрос.

Перезапуск процесса между пунктами 2 и 4 не удаляет контекст. История ограничена
12 сообщениями (примерно шесть пар вопрос/ответ); профиль и pending хранятся отдельно.
Автоматического удаления диалогов по сроку пока нет.
Ключ памяти — Telegram user ID, как в вашем контракте; обработка рассчитана
на личные сообщения, что уже ограничено фильтром Telegram-роутера.

`/new` очищает историю, профиль и последнее уточнение пользователя, а также
убирает текущую карточку неподтверждённого черновика.
`/cancel` отменяет незавершённый запрос/черновик и сохраняет профиль.
Уже созданные напоминания управляются через `/reminders`.

В одном процессе сообщения одного пользователя обрабатываются последовательно.
При нескольких процессах сравнение `version` предотвращает перезапись более
нового состояния; проигравший обработчик просит повторить сообщение.
Длинная SQL-транзакция во время запроса к DeepSeek не удерживается.

## Проверить assistant без Telegram

Нужны PostgreSQL, собранный индекс и ключ DeepSeek. Используйте отдельный
тестовый ID, чтобы не менять историю реального пользователя:

```powershell
python -m alfa_bot.assistant.chat --user-id 999000001
```

Команды `/new`, `/cancel`, `/exit` доступны в консоли.
Консоль печатает `Reply`; напоминание в ней не создаётся и не отправляется.

## Модули и границы ответственности

| Файл | Что делает |
| --- | --- |
| `knowledge/models.py` | Материал, документ и найденный фрагмент |
| `knowledge/parsing.py` | Нормализация NBSP/переносов, токенизация, русский стемминг |
| `knowledge/ingestion.py` | Читает JSONL, проверяет допуск и публикует снимок индекса |
| `knowledge/repository.py` | Загружает снимок, считает BM25 и гибридный рейтинг |
| `knowledge/service.py` | `retrieve`, `recommend`, `get_card` |
| `knowledge/ingest.py` | Команда сборки индекса |
| `knowledge/search.py` | Команда проверки поиска |
| `assistant/models.py` | ORM-таблица `assistant_dialogs` |
| `assistant/repository.py` | Загрузка и сохранение диалога с проверкой версии |
| `assistant/schemas.py` | Проверка структурированного вывода LLM |
| `assistant/prompts.py` | Правила маршрутизации и ответа по источникам |
| `assistant/validation.py` | Проверка будущей даты, IANA-пояса и переходов часов |
| `assistant/service.py` | Реализация `AssistantPort.handle()` |
| `assistant/chat.py` | Ручная проверка диалога без Telegram |
| `infra/embeddings.py` | Локальный E5, вычисления вне event loop |
| `infra/llm.py` | DeepSeek, JSON mode, валидация, ограниченные повторы |
| `main.py` | Собирает зависимости и передаёт настоящий assistant в Dispatcher |

`AssistantPort.handle(telegram_user_id, text, now)` принимает именованные
аргументы по существующему контракту. `now` должен содержать часовой пояс.
Метод возвращает один из `ANSWER`, `CLARIFICATION`, `REMINDER`, `OUT_OF_SCOPE`.
Поиск `retrieve(query, limit=6)` возвращает `list[SearchHit]`; рекомендации
`recommend(query, kind="any", access="any", limit=2)` возвращают подходящие
материалы; `get_card(material_id)` возвращает `MaterialCard | None`.

Классификация требует одного запроса LLM. Готовый ответ по источникам — второго.
Подбор карточек и проверка данных напоминания выполняются сервером.
История, профиль и извлечённые публичные фрагменты передаются настроенному LLM-провайдеру.
Напоминания в assistant не создаются и не изменяются.

## Проверки и границы результата

```powershell
python -m pytest -q
python -m ruff check src/alfa_bot/assistant src/alfa_bot/knowledge src/alfa_bot/infra src/alfa_bot/main.py tests
```

См. `docs/VALIDATION.md`: результаты проверок и что требует проверки на вашей машине.
Тесты LLM используют HTTP-mock и контролируемые ответы. Они проверяют обработку
контрактов и ошибок, но не заменяют оценку качества ответов настоящей модели.

Индекс собирается отдельной командой. Чтобы обновить материалы, повторите
сборку и перезапустите бот: работающий процесс использует загруженный снимок.
Обновление указателя CURRENT атомарно; неудачная сборка оставляет прежний снимок рабочим.
